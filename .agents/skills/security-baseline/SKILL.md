# Базовая безопасность

Источник фактов — текущий код и `docs/security/network.md`, `docs/security/pki.md`, `docs/deploy/vds.md`. Часть III `pki.md` описывает цель, а не текущий выпуск сертификатов.

Обязательное в текущем коде:

- На хост наружу открыты только порты 80 и 443 Caddy.
- Публичный вход требует mTLS `require_and_verify` и заголовок `X-Proxy-Secret`. Пустой секрет не подменяется запасным значением.
- PostgreSQL подключается с `POSTGRES_SSLMODE=verify-full`. Redis слушает только TLS. MinIO ходит по HTTPS.
- Закрытые ключи лежат в отдельных томах. Общий `certs_data` не монтируют во все сервисы.
- `root-ca` сам подписывает сертификаты сервисов на 365 дней и промежуточный `enclave-intermediate-ca` на 90 дней. Этот промежуточный сертификат листья не подписывает. Корню 10 лет.
- Анклава Intel SGX нет. Проверка `X-Enclave-Signature` смотрит подпись и открытый ключ. Закрытый ключ в процесс API не кладут.
- `STRICT_SECURITY=true` не обходят флагом `FINANCIAL_AI_ALLOW_TEST_BRIDGES` в боевом запуске. Этот флаг допустим только в тестах.
- `debug=True` и встроенный запасной суперпользователь в сервере не включают.

Новый обход, запасной секрет или ослабление `verify-full` до `require` считают дефектом, даже если старый черновик документа так написан.
